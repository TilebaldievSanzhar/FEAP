## 1. Что реализовано

### 1.1. База данных (миграция 005 + 006)

Три таблицы для хранения мер НТР:

| Таблица | Назначение | Записей (начально) |
|---------|-----------|-------------------|
| `ntm_measure_types` | Справочник 13 типов мер (из TWS.BY R12 Kind) | 13 |
| `ntm_measures` | Конкретные меры (ТР, лицензии, запреты...) | 36 (из data/ntm_seed.json) |
| `ntm_measure_codes` | Привязка мер к кодам ТН ВЭД (M:N) | 157 (из data/ntm_seed.json) |

**Ключевые поля:**
- `ntm_measures.scope` — `eaeu` для общих мер ЕАЭС, `national` для специфичных КР
- `ntm_measures.data_source` — источник данных (`tws_by`, `tks_ru`, `manual`, `eec`)
- `ntm_measure_codes.product_description` — квалификатор из НПА (для двойного соответствия)
- `ntm_measure_codes.applies_to_children` — применяется ли мера к дочерним кодам

**Миграция 006:** Удалено поле `verification_context` из `ntm_measures` — оно было избыточным.
Квалификаторы хранятся в `ntm_measure_codes.product_description` на уровне связи код-мера.

### 1.2. ORM модели

Файл: `src/feap/db/models.py`

- `NtmMeasureType` — тип меры
- `NtmMeasure` — конкретная мера
- `NtmMeasureCode` — привязка к коду ТН ВЭД

### 1.3. Database queries

Файл: `src/feap/db/queries.py`

- `get_ntm_measures_for_code(session, code)` — получить все НТР меры для 10-значного кода
  - Проверяет точное совпадение + все родительские префиксы (8, 6, 4, 2 знака)
  - Учитывает флаг `applies_to_children`
  - Фильтрует по `valid_from`/`valid_to` на обоих уровнях (мера + связь)
- `get_ntm_measure_types(session)` — справочник типов

### 1.4. API эндпоинты

| Эндпоинт | Метод | Описание |
|----------|-------|----------|
| `/api/v1/ntm/{code}` | GET | Нетарифные меры для кода (lookup по коду, без верификации) |
| `/api/v1/ntm/verify` | POST | **LLM-верификация двойного соответствия** (код + описание товара) |
| `/api/v1/tnved/lookup/{code}` | GET | Включает блок `ntm` (lookup, без верификации) |

### 1.5. Архитектура: НТР отделён от каскада классификации

```
POST /classify → каскад L0..L5 → ClassificationResult (без НТР)

POST /ntm/verify (отдельный сервис)
     Вход: code (10 знаков) + product_description
     │
     ├── Lookup мер по коду (prefix match + applies_to_children)
     │
     ├── Если есть квалификаторы → LLM-верификация
     │   (сопоставление описания товара с product_description каждой меры)
     │
     └── Выход: measures[] со статусами:
             applies — мера точно применяется
             does_not_apply — мера не применяется (товар не подпадает)
             uncertain — недостаточно данных
```

**Почему НТР отделён от каскада:**
- Разная бизнес-логика (классификация vs проверка мер)
- Разные данные (дерево/ОПИ/пояснения vs перечни НПА)
- Разный цикл обновления (НТР меняется 5-10 раз в год)
- Ошибки НТР не влияют на классификацию и наоборот

### 1.6. LLM-верификация двойного соответствия

Модуль: `src/feap/ntm/verifier.py`

**Принцип:** Мера НТР применяется к товару, только если:
1. Код ТН ВЭД совпадает (проверено программно)
2. Описание товара соответствует квалификатору меры (проверяется LLM)

**Логика:**
- Если у меры нет квалификатора (`product_description` = NULL) → `applies` (применяется ко всем товарам кода)
- Если квалификатор есть → LLM сравнивает описание товара с квалификатором
- При ошибке LLM → fallback к `may_apply`

**Модель:** Лёгкая (Haiku/Flash) — задача классификационная, быстрая.

**Промпт:** `prompts/templates/system/ntm_verify.jinja2`

### 1.7. Начальные данные (seed)

**Справочник типов** (`scripts/seed_ntm_types.py`): 13 типов мер НТР.

**Меры и привязки к кодам** (`scripts/seed_ntm_data.py` + `data/ntm_seed.json`):

| Категория | Кол-во мер | Привязок к кодам | Источник |
|-----------|-----------|-----------------|----------|
| Технические регламенты (kind=6) | 26 | 118 | НПА ЕЭК |
| Лицензирование (kind=4) | 7 | 24 | Решение Коллегии ЕЭК № 30 |
| Санитарный контроль (kind=7) | 1 | 20 | Решение КТС № 299 |
| Ветеринарный контроль (kind=8) | 1 | 8 | Решение КТС № 317 |
| Фитосанитарный контроль (kind=9) | 1 | 6 | Решение КТС № 318 |
| **Итого** | **36** | **157** | |

Привязки на уровне 2-4 значных кодов (группы/позиции) с `applies_to_children=true`.
Квалификаторы (`product_description`) заполнены для мер, где важно двойное соответствие.

`seed_db.py` вызывает seed последовательно: types → measures. Идемпотентно — пропускает, если данные есть. `--force` для перезаписи.

**Ограничение текущего seed:** русские PDF-перечни к ТР на сайте ЕЭК — сканы (не текстовые), поэтому точные 10-значные коды из перечней не извлечены. Текущие привязки на уровне групп (2-4 знака) — достаточно для MVP. Для точных привязок нужен TWS.BY R12 API или OCR.

## 3. Двойное соответствие (код + описание)

### Проблема

Во всех перечнях НТР используется принцип: код ТН ВЭД **И** наименование товара.
Чисто кодовый lookup даёт приблизительный результат.

### Решение

LLM-верификация через `POST /api/v1/ntm/verify`:

1. По коду находятся все потенциально применимые меры (prefix match)
2. Для мер с квалификаторами (`product_description`) LLM проверяет соответствие
3. LLM получает описание товара + квалификаторы всех мер в одном запросе
4. Возвращает вердикт по каждой мере: `applies` / `does_not_apply` / `uncertain`

### Пример

```
Товар: "Электрическая зубная щётка, 3.7V, аккумулятор Li-Ion"
Код: 8509800000

Мера: ТР ТС 004/2011 "О безопасности НВО"
Квалификатор: "электрические аппараты, работающие от сети
              переменного тока напряжением от 50 до 1000 В"

→ LLM: "Зубная щётка работает от 3.7V аккумулятора, не от сети 50-1000V"
→ Статус: does_not_apply
```

### Формат ответа POST /api/v1/ntm/verify

```json
{
  "code": "8509800000",
  "code_formatted": "8509 80 000 0",
  "name": "прочие",
  "product_description": "Электрическая зубная щётка...",
  "measures": [
    {
      "measure_type": "Соответствие техническим регламентам",
      "measure_type_kind": 6,
      "name": "ТР ТС 004/2011",
      "status": "does_not_apply",
      "qualifier": "электрические аппараты, работающие от сети...",
      "reasoning": "Товар питается от аккумулятора 3.7V, не от сети 50-1000V",
      "legal_basis": "Решение Коллегии ЕЭК № 91",
      "scope": "eaeu"
    },
    {
      "measure_type": "Электромагнитная совместимость",
      "measure_type_kind": 6,
      "name": "ТР ТС 020/2011",
      "status": "applies",
      "qualifier": null,
      "reasoning": "Квалификатор отсутствует — мера применяется по совпадению кода",
      "scope": "eaeu"
    }
  ],
  "total_count": 2,
  "verified": true,
  "has_technical_regulations": true
}
```

## 4. TODO

### 4.1. Точные привязки кодов (10 знаков) из TWS.BY R12 API

**Проблема:** Текущий seed содержит привязки на уровне групп (2-4 знака). Точные 10-значные коды из перечней к ТР недоступны — русские PDF на сайте ЕЭК являются сканами (не текст), DOCX доступны только на кыргызском/казахском/белорусском языках.

**Решение:** Интеграция с TWS.BY R12 API.
- API возвращает все 13 типов НТР мер с точными кодами (JSON)
- Требует платный Token + Hash (аутентификация через R1)
- При получении доступа: `TwsApiClient` (httpx, async) → кэширование ответов в `ntm_measures` + `ntm_measure_codes`

**Альтернатива:** OCR русских PDF-перечней через Tesseract/Cloud Vision.
