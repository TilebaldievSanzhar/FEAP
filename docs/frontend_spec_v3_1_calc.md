# Frontend FEAP — дополнение v3.1: суммы и себестоимость в расчёте, паспорт PDF, ввод по фото

> **Как читать этот документ.** Это **дельта** к `frontend_spec_v3_ia.md` (экраны v3 уже
> нарисованы и реализованы: `/calc`, решение по мере защиты рынка, справочники, паспорт
> товара `/catalog/$sku`). Здесь — только изменения. Документ самодостаточен: контракты и
> JSON-примеры взяты из живых ответов бэкенда (14.10.2026).

## 1. Что появилось в бэкенде

1. **`POST /api/v1/calc` — расчёт сумм по товару без досье.** Партия (код, страна,
   стоимость, базис поставки, количество, расходы) → платежи графы 47 и сбор,
   таможенная стоимость, **себестоимость ввоза** всего и на единицу. Считает тот же
   сборщик, что и проект ДТ: суммы совпадают с проектом по такой же позиции до копейки.
   LLM нет — запрос дешёвый, его можно пересчитывать при каждом изменении формы.
   Открыт без входа (как справка по коду).
2. **Паспорт товара хранится в «Товарах».** У записи каталога новое поле `passport`:
   параметры партии и обоснование кода. Суммы не хранятся — паспорт пересчитывается
   на дату по актуальным ставкам.
3. **PDF паспорта:** из расчёта (`POST /api/v1/calc/passport.pdf`, без входа) и из
   записи «Товары» (`GET /api/v1/catalog/{id}/passport.pdf`). Кнопки «Скачать PDF ·
   скоро» становятся рабочими.
4. **Ввод по фото или скриншоту** (`POST /api/v1/calc/from-image`): скриншот карточки
   товара с 1688/Taobao/Wildberries или фото товара/этикетки → описание для
   классификации на русском + подсказки формы (страна, производитель, цена за
   единицу). Это вызов LLM (как классификация): нужен вход в режиме `required`,
   учитывается в использовании.

Принципы не меняются: деньги считает только бэкенд (на клиенте — только отображение);
`needs_input` вместо тихих нулей; подпадание под меру решает человек.

## 2. `/calc` — шаг 1 «Что за товар»: третий режим «Фото / скриншот»

Переключатель режимов: **Описание товара · Знаю код ТН ВЭД · Фото или скриншот**.

```
┌ Фото или скриншот ─────────────────────────────────────────────────────┐
│ [ Перетащите до 4 изображений одного товара или выберите файлы ]       │
│   JPEG, PNG, WebP · до 8 МБ · скриншот карточки 1688/Taobao или фото   │
│ Комментарий (необязательно): [для кухни, крышка в комплекте…]          │
```

- `missing_info` / `clarifying_questions` (если есть) — показать над кнопкой как
  подсказку «чего не видно на фото», не блокировать.

## 3. `/calc` — шаг 1: параметры партии (для сумм)

Сейчас форма спрашивает страну, стоимость и дату. Добавить (компактно, вторичным
уровнем — «Подробнее о партии ▾», раскрыт при вводе по фото):

| Поле | Контракт `CalcIn` | Примечание |
|---|---|---|
| Базис поставки | `incoterms` (EXW…DDP), по умолчанию `FOB` | селект; подсказка, что входит в цену |
| Фрахт до границы ЕАЭС | `freight_to_border` (в валюте счёта) | показывать для EXW/FCA/FAS/FOB; без него — предупреждение W-FREIGHT |
| Страховка / прочие до границы | `insurance`, `other_charges` | вторично |
| Количество + единица | `qty`, `qty_unit` | для себестоимости **на единицу** |
| Производитель | `manufacturer` | если у меры защиты рынка есть ставки по производителям |
| Вес нетто / брутто, доп. единица | `net_kg`, `gross_kg`, `supp_qty`, `supp_unit` | нужны только для специфических ставок; бэкенд сам скажет `missing_parameters` |
| Расходы после границы | `costs[]`: `{kind, label?, amount, currency}` | список строк: доставка по КР, брокер, СВХ, сертификация, банк, прочее |

`kind`: `logistics | broker | warehouse | certification | bank | other`; валюта —
`KGS` по умолчанию или любая с курсом НБКР (`USD`, `EUR`, `CNY`, `RUB`, `KZT`).

## 4. `/calc` — шаг 3: суммы и себестоимость вместо «посчитает проект ДТ»

Правая карточка «Суммы платежей» (сейчас — текст «суммы посчитает проект ДТ»)
становится живой: при наличии стоимости фронт вызывает `POST /api/v1/calc` и
пересчитывает при изменении параметров (debounce ~400 мс).

```
┌ Платежи · на 14.10.2026 · курс 87,45 ─────────────┐
│ Таможенная стоимость          874 500,00 сом       │
│ Пошлина 9%                     78 705,00           │
│ ● Антидемпинговая AD-32 21,89% 191 428,05          │
│ НДС 12%                       114 384,60           │
│ Сбор за таможенные операции     3 498,00           │
│ Итого платежей                388 015,65 сом       │
├ Себестоимость ввоза ──────────────────────────────┤
│ Товар по счёту                874 500,00           │
│ Платежи                       388 015,65           │
│ Брокер / доставка …            58 725,00           │
│ ИТОГО                       1 321 240,65 сом       │
│ на 1 шт: 1 321,24 · без НДС 1 206,86               │
│ ⓘ НДС 114 384,60 плательщику НДС — к зачёту        │
└───────────────────────────────────────────────────┘
```

- **Мера защиты рынка без решения.** Ответ `status: "needs_input"`, в
  `missing_parameters` — строка с `remedy_decisions['AD-32']`. Суммы платежей без меры
  при этом есть (`payments` без строки 2050), но `landed_cost = null`. Показать прямо в
  карточке компонент «Решение по мере» (тот же, что в позиции досье, §4.1 спеки v3) — в
  расчёте решение отправляется в `remedy_decisions` запроса. Без решения итог не
  показывать.
- `payments_total = null` — какой-то платёж не рассчитан (нет веса для специфической
  ставки и т.п.): показать строки с «не рассчитано» и `missing_parameters` как
  «Не хватает данных» с переходом к нужному полю.
- `findings` — только правила, осмысленные без досье: F-03, F-06, F-07, F-08, F-10,
  F-14, F-16, F-17, W-FREIGHT, W-FEE, W-FTA, I-EAEU, W-REMEDY-*, W-VAT-COND, I-VAT-COND.
  Показывать компактно под карточкой (тот же FindingRow).
- Сбор считается на одну ДТ — мелкой подписью «сбор — на одну декларацию».
- `vat_base_includes_remedies` — подпись, как в проекте ДТ.

## 5. Шаг 4 «Дальше»: PDF и сохранение паспорта

- **«Скачать PDF»** (сейчас disabled «скоро») → `POST /api/v1/calc/passport.pdf`, без
  входа. Тело: `{ "calc": <тот же CalcIn>, "title": "<название товара>", "sku": null,
  "classification": <см. ниже или null> }` → `application/pdf`.
  Содержимое: код и цепочка «раздел → … → код», обоснование каскада (если передано),
  ставки и меры, расчёт платежей, себестоимость, проверки, дисклеймер.
- **«Сохранить в «Товары»»** — к `POST /api/v1/catalog` добавляется `passport`:
```json
{
  "sku": "POT-24",
  "description": "Кастрюли литые алюминиевые",
  "hs_code": "7615101000",
  "attributes": {},
  "passport": {
    "calc": { "origin_country": "CN", "manufacturer": null, "price": "10000", "currency": "USD",
              "incoterms": "DAP", "qty": "1000", "qty_unit": "шт",
              "remedy_decisions": { "AD-32": { "decision": "applies" } },
              "costs": [{ "kind": "broker", "amount": "15000", "currency": "KGS" }] },
    "classification": {
      "source": "cascade",
      "confidence": 0.94,
      "steps": [
        { "level": "position", "code": "7615", "name": "Изделия столовые, кухонные…", "reasoning": "ОПИ 1: …" }
      ]
    }
  }
}
```
  `classification.source`: `cascade` (код из каскада — шаги из `classification_chain`
  ответа классификации), `manual` (код введён руками), `catalog` (из утверждённой
  записи). `passport: null`/отсутствует — сохранённый паспорт не меняется; объект —
  заменяет целиком. Невалидный паспорт → `422`.

## 6. Паспорт товара `/catalog/$sku` — расчёт для партии

`CatalogItemOut` теперь содержит `passport` (`{}` у старых записей).

- Новая секция **«Расчёт для партии»**: параметры из `passport.calc` (редактируемые,
  тот же блок полей, что в §3) + живой пересчёт `POST /api/v1/calc` на сегодня
  (`hs_code` и `description` — из записи). Кнопка «Сохранить параметры» →
  `POST /api/v1/catalog` с `passport`.
- Секция «Код и обоснование» показывает `passport.classification.steps` (с reasoning),
  если есть; иначе — цепочку кода, как сейчас.
- **«Паспорт PDF»** (сейчас «скоро») → `GET /api/v1/catalog/{id}/passport.pdf?on_date=`.
  Без `passport.calc.price` PDF содержит ставки и меры без сумм. Чужая запись → `404`,
  нет кода → `422`.
- «В новую поставку» — переносить также `origin_country`, `manufacturer`,
  `remedy_decisions`, `price`/`currency` из паспорта.

## 8. Открытые вопросы к дизайну

1. Где жить параметрам партии на `/calc`: под основной формой (раскрывашка) или в
   правой колонке результата (меняешь — видишь пересчёт)?
2. Как подать «две цены» — с НДС и без НДС на единицу — чтобы частный покупатель (не
   плательщик НДС) и компания (плательщик) сразу видели свою.
3. Как показать, что цена распознана с картинки и её нужно подтвердить, не превращая
   форму в «красную»?
