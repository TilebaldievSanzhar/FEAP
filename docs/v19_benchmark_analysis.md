### 3.2 Детальный разбор L4

#### M09 — Апельсиновый сок, число Брикса не указано

- **Продукт**: Сок апельсиновый восстановленный из концентрата, 100%, 1 литр
- **SGR parameter_extraction**: «число Брикса = НЕ УКАЗАНО» — **корректно**
- **Проблема**: Модель УГАДАЛА Brix (~11.2-11.8) и выбрала 200912 (Brix ≤20) вместо 200919 (прочие)
- **Корневая причина**: Модель «додумывает» недостающий параметр вместо выбора «прочие»
- **Категория**: Конкретный vs «прочие»

#### M18 — Хирургические перчатки, код 401512 не найден

- **Продукт**: Перчатки хирургические стерильные, латексные
- **Проблема**: В контексте дерева модель видит 401511 (хирургические), но GT = 401512 (медицинские/хирургические). Итоговый selected = 401590 (прочие)
- **Корневая причина**: Код 401512 вероятно не попал в контекст или модель не различает 401511 vs 401512
- **Категория**: Навигация по дереву

#### M22 — Свитер из мериноса, шерсть vs тонкое волокно

- **Продукт**: Свитер 100% шерсть мериноса
- **SGR**: «шерсть мериноса = шерстяная пряжа → 611011»
- **Проблема**: В ТН ВЭД «из шерстяной пряжи» (611011) может иметь весовой порог (≥600г). Свитер ~400-500г → 611019 (прочие). Модель не знает про вес
- **Корневая причина**: Отсутствие доменного знания о весовых порогах внутри текстильных субпозиций
- **Категория**: Домен / скрытый порог

#### M27 — Фитинги: муфты ≠ колена

- **Продукт**: Фитинги стальные резьбовые (муфты, угольники, тройники)
- **SGR**: Модель обобщила все резьбовые фитинги → 730792 (колена, отводы и сгоны с резьбой)
- **Проблема**: 730792 конкретно покрывает «колена, отводы и сгоны», а муфты и тройники → 730799 (прочие)
- **Корневая причина**: Модель не различает типы фитингов; выбирает «похоже» вместо «точно соответствует»
- **Категория**: Текстовое обобщение

#### M39 — Прицеп для легкового авто ≠ грузовой

- **Продукт**: Прицеп для легкового автомобиля, грузоподъёмность 500 кг
- **SGR**: «грузоподъёмность = 500 кг» — модель решила что это грузовой прицеп → 871639
- **Проблема**: Бытовой прицеп для легкового авто → «прочие» (871640), а не «грузовые» (871639)
- **Корневая причина**: Модель не знает, что бытовой прицеп ≠ грузовой
- **Категория**: Домен: бытовой vs грузовой

#### H02 — МФУ: «2+ функции» vs «подключение к ЭВМ» (стабильная ошибка)

- **Продукт**: МФУ лазерное: печать, сканирование, копирование, факс
- **SGR**: «МФУ → 844331 (2+ функции)» с confidence=1.0
- **Проблема**: 844331 = «выполняющие 2+ функции», 844332 = «прочие, имеющие возможность подключения к ЭВМ». МФУ с USB/Wi-Fi → 844332, но модель считает 844331 конкретнее
- **Корневая причина**: Текстовая ловушка — «2+ функции» звучит точнее для МФУ, хотя правильный код определяется подключением к ЭВМ
- **Категория**: Текстовая ловушка (стабильная, воспроизводится из v14)

#### H19 — Пикап 3.1т: порог полной массы

- **Продукт**: Пикап, дизель 2.4л, масса снар. 2100 кг, грузоподъёмность 1т
- **SGR parameter_extraction**: «двигатель = дизельный 2.4 л, грузоподъёмность = 1 тонна, масса снаряжённого ТС = 2100 кг» — **корректно**
- **SGR threshold_comparison**: Модель рассчитала полную массу ~3.2т → 870421 (≤5т)
- **GT**: 870423 (>5т) — **возможно спорный GT**
- **Корневая причина**: Если полная масса действительно ~3.2т, то 870421 (≤5т) логичен. SGR сработал правильно
- **Категория**: Порог (SGR работает, GT спорный)

#### H30 — Bluetooth колонка: 2 динамика = «одиночный»

- **Продукт**: Колонка портативная, два динамика + пассивный излучатель
- **SGR**: «два динамика → комплект → 851822»
- **Проблема**: В ТН ВЭД два динамика в ОДНОМ корпусе = «одиночный громкоговоритель» (851821), а «комплект» (851822) = несколько ОТДЕЛЬНЫХ колонок
- **Корневая причина**: Модель не знает терминологию ТН ВЭД для громкоговорителей
- **Категория**: Домен: терминология

### 4.3 Детальный разбор ключевых паттернов L5

#### Паттерн «Невидимый код» (5 кейсов)

Модель попадает в ветку через L5a shortlist, но GT-код находится в ДРУГОЙ ветке того же уровня.

Примеры:
- **M04** (рис): chain → `1006309600`, GT = `1006309809`. Модель видит одну ветку «длиннозёрный» и auto-select единственный код в ней. GT-код в другой ветке «прочие».
- **M36** (ТВ): chain → `8528724000`, GT = `8528722001`. Модель попала в ветку «аппаратура ≤42 см» вместо «≤75 см».
- **H08** (кабель): chain → `8544499900`, GT = `8544499108`. Модель видит единственный код в ветке и auto-select.

**Корневая причина**: L5a shortlist направляет в неверную ветку, или дерево не показывает все доступные коды.

#### Паттерн «Конкретный vs прочие» (6 кейсов)

Модель последовательно выбирает конкретный (по её мнению) код вместо «прочие».

Примеры:
- **E03** (молоко): SGR правильно определил «без сахара, >2.5кг», но выбрал 0402109900 вместо 0402101900. Разница: `1900` = без сахара (конкретный), `9900` = прочие. Модель путает иерархию кодов
- **M34** (электродвигатель): SGR правильно определил «асинхронный» → 8501522001. GT: 8501522009 (прочие). Модель точно следует описанию кода, но GT говорит иначе
- **H10** (PS5): SGR → «с использованием ТВ приёмника» → 9504500001. GT: 9504500009 (прочие)

**Корневая причина**: Модель не понимает тонкую иерархию 10-значных кодов. Когда описание конкретного кода «звучит правильно», модель выбирает его, даже если в реальности товар попадает в «прочие» по более глубокой иерархической логике.

### Главные системные проблемы

1. **«Конкретный vs прочие» (39%)** — самая частая ошибка. Модель систематически предпочитает код, чей текст «звучит подходяще», вместо «прочие». SGR-поле `why_not_residual` не помогает — модель его заполняет, обосновывая свой (неправильный) выбор. Нужен обратный механизм: «ПОЧЕМУ этот код, а не прочие — ПРОЦИТИРУЙ, где товар ТОЧНО соответствует КАЖДОМУ слову текста кода».

2. **«Невидимый код / неверная ветка» (26%)** — L5 handler/shortlist направляет в неправильную ветку 8-значных кодов. GT-код находится в другой ветке. Это проблема L5a shortlist, не SGR-полей.

3. **«Домен / терминология» (22%)** — модель не знает специфическую терминологию ТН ВЭД (колонка с 2 динамиками = «одиночный»; бытовой прицеп ≠ грузовой). Решается few-shot примерами или пояснениями в контексте.

## 6. Эффективность SGR-изменений v19

### Что сработало

- **`parameter_extraction`** — корректно извлекает числовые параметры во всех кейсах
- **`threshold_comparison`** — корректно сопоставляет с порогами. **Ни одной ошибки из-за неправильного числового сравнения**
- Проблема числовых порогов из v16 (4/6 ошибок) — **решена**
- Стабильность каскада: 0 системных ошибок, 99% completion rate
- flash-lite через json_object + prompt стратегию работает надёжно (retry помогает при validation errors)

### Что не сработало

- **`why_not_residual`** — модель заполняет поле, обосновывая свой (неправильный) выбор конкретного кода. Поле не заставляет модель сомневаться
- L5 SGR-поля (`code_differentiation`, `threshold_comparison`) работают, но не решают проблему навигации по дереву

## 7. Рекомендации для v20

### Приоритет 1: «Конкретный vs прочие» (9 ошибок, 39%)

**Гипотеза**: Нужен SGR-механизм, который заставляет модель проверить, соответствует ли товар КАЖДОМУ слову текста конкретного кода.

Варианты:
- Новое SGR-поле `exact_text_match_check`: «Процитируй текст выбранного кода. Соответствует ли товар КАЖДОМУ слову? Если хотя бы одно слово не подходит → выбери прочие»
- Усилить промпт: «Код X покрывает ТОЛЬКО [конкретное]. Если товар = [более общее], выбери прочие»

### Приоритет 2: «Невидимый код / неверная ветка» (6 ошибок, 26%)

**Гипотеза**: L5a shortlist выбирает ветку 8-значного кода, но GT-код в другой ветке.

Варианты:
- Расширить L5a shortlist до 2-3 веток вместо одной
- Показывать ВСЕ 10-значные коды субпозиции без предварительной фильтрации по ветке
- Проверить формат дерева в контексте L5

### Приоритет 3: «Домен / терминология» (5 ошибок, 22%)

Варианты:
- Few-shot примеры в промптах L4/L5 для конкретных ловушек (МФУ, динамики, прицепы)
- Подгрузка пояснений к субпозициям (если доступны)
