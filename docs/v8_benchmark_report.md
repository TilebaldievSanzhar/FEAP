## 3. Что изменилось в v8

### 3.1 Модель: gemini-3.1-flash-lite-preview → gemini-2.5-flash

Ключевое изменение. gemini-2.5-flash — thinking-модель с внутренним chain-of-thought.

**Эффект:**
- Модель реально «думает» перед ответом — применяет ОПИ последовательно
- Следует сложным промпт-инструкциям (flash-lite их игнорировала)
- Стабильный structured output (JSON)
- Ноль false needs_input (flash-lite выдавала 15 ложных остановок)

### 3.2 L1 двухшаговая оптимизация

Вместо загрузки всех 533 примечаний к разделам (~14K токенов):

- **Шаг 1a (shortlist):** LLM выбирает 2-3 кандидата по названиям разделов (без примечаний)
- **Шаг 1b (verify):** загружаются примечания только к 2-3 кандидатам, LLM проверяет исключения

**Экономия:** ~60-79% токенов на L1.

### 3.3 Thinking config

Добавлен `ThinkingConfig(thinkingBudget=1024)` — ограничивает thinking tokens, предотвращает обрезку JSON.

## 5. Latency и стоимость

### Latency

|:-----------|:--:|:--:|:-:|

Latency выросла x3 из-за thinking tokens. Это ожидаемый trade-off: качество vs скорость.

### Стоимость (оценка)

**gemini-3.1-flash-lite-preview:** $0.25 / $1.50 per MTok (input/output)
**gemini-2.5-flash:** pricing зависит от thinking tokens — нужно проверить точные цены.

Учитывая что v8 не генерирует ложные needs_input (15% экономии на повторных запросах) и что heading accuracy 94% vs 80% — **стоимость за правильную классификацию** может быть сопоставима.

## 6. Оставшиеся проблемы

### 6.1 JSON truncation (2 errors)
BENCH-M20 и BENCH-M25 упали с `Unterminated string` на L1 shortlist. `thinkingBudget=1024` не всегда достаточен. Варианты:
- Увеличить thinkingBudget
- Добавить retry с увеличенным max_output_tokens
- JSON repair (дополнить обрезанный JSON)

### 6.2 Субпозиции (L4-L5)
11 из 27 ошибок — на уровне subheading. Это уровни L4/L5, где нужны точные технические параметры. Возможные улучшения:
- Улучшить промпты L4/L5
- Подгружать больше пояснений на уровне субпозиций
- Использовать прецеденты (RAG)

### 6.3 Section-level ошибки (4 кейса)
4 ошибки на уровне раздела — самые дорогие, т.к. каскад идёт по неверному пути. Нужен анализ конкретных кейсов.

## 7. Выводы

1. **gemini-2.5-flash кардинально превосходит flash-lite** для задач таможенной классификации: +14 heading accuracy, +11 code-10
2. **Thinking capabilities — ключевой фактор**: модель реально применяет ОПИ правила последовательно
3. **Ноль ложных needs_input** — модель уверенно классифицирует без запроса уточнений
4. **Trade-off: latency x3** (50 sec vs 16 sec), но качество несопоставимо выше
5. **L1 двухшаговая оптимизация работает корректно** — shortlist стабильно отбирает верные разделы
6. **Главный bottleneck сместился** с heading (L1-L3) на subheading (L4-L5) — следующий фокус оптимизации
