# Верификатор условий: реализация Этапа 1 (E2-lite)

5 ноября 2026 года, ветка `decision-engine`. План — [decision_engine_plan.md](decision_engine_plan.md), §5 и §7;
что и как оценивается — [decision_engine_preregistration.md](decision_engine_preregistration.md).

Верификатор проверяет код, выбранный каскадом, и альтернативы из его трассы по сырым текстам строк ЕТТ. Код
каскада он не меняет: на выходе сигналы S1–S7 и флаги политик P1–P3. В продукт и каскад модуль пока не подключён.

---

## 1. Как устроено

```text
описание → нумерованные фрагменты (feap.cascade.evidence.source_spans, как в v32)
код каскада + кандидаты трассы L3–L5
        │
rows: строки ЕТТ позиции из name_full листьев (путь ЕЭК через «: 🠺 », порядок кодов)
        │
conditions: путь кода, соседи на развилках, пути альтернатив, соседи до «прочие»
        │
исполнитель: семантика → supported / contradicted / not_stated
извлечение (один раз на величину, кеш на набор): число + единица + фрагмент → сравнение в коде
режим: F по презумпции «не заявлен»
        │
signals: Клини, остаток → S1–S7 → P1–P3
```

| Модуль | Что делает |
|---|---|
| `src/feap/decision/contracts.py` | `Condition`, `DecisionQuestion`, `DecisionAnswer`, `ConditionStatus`, `Signal`, `VerifyTrace` |
| `logic.py` | Клини, остаток, числа с десятичной запятой, единицы, интервалы, сравнение факта с интервалом |
| `rows.py` | дерево строк позиции: путь, соседи по порядку, строка кода любой длины, позиции группы |
| `conditions.py` | типизация строк и набор условий кейса |
| `signals.py` | статусы → сигналы → флаги политик |
| `backend.py` | интерфейс исполнителя, вопросы, проверка ответов, ответ → статус |
| `providers/openrouter.py` | плечи V1 (вопрос на вызов) и V2 (все вопросы одним вызовом), извлечение чисел |
| `verifier.py` | один кейс целиком |
| `benchmark/scripts/verify_replay.py` | прогон плеча на готовых трассах; DRY — без вызовов, с оценкой цены |
| `benchmark/scripts/score_verify.py` | H1, H2, стоимость и решение §8 предрегистрации |

## 2. Правила, которые замораживаются перед dev150

Версия вопросов — `QUESTIONS_VERSION = e2lite-1`. Любая правка правил ниже меняет версию.

### 2.1 Какие условия проверяются

- **Путь кода:** текст позиции и все строки до листа.
- **Соседи на каждой развилке пути.** У широкой развилки — до 15 ближайших по порядку; строка пути всегда среди них.
- **Альтернативы** — коды из трассы каскада: `ShortlistResult`, `PositionResult`, `SubpositionResult`,
  `SubsubpositionShortlistResult`, `SubsubpositionResult`.
  - Альтернатива на самом пути каскада не считается.
  - Код без строки в справочнике записывается в заметки кейса.
- **Для каждого «прочие»** — предшествующие конкретные соседи. Для «прочие» на пути альтернативы — до 15 последних.
  Непроверенный сосед считается U.
- **«Прочие» в тексте позиции** («Мебель прочая и ее части», 9403) — остаток среди позиций группы: он исключает
  предшествующие позиции, до 15 последних.

### 2.2 Типы строк

| Тип | Признак | Как решается |
|---|---|---|
| режим | сноска «5)» в конце или «в порядке, указанном в дополнительном примечании…» | F по презумпции «режим не заявлен»; на пути кода — S7 |
| остаток | «прочие / прочий / прочая / прочее», не после «и» / «или» | ¬(предшествующие конкретные соседи) по Клини |
| остаток с уточнением | «креветки прочие», «прочие, с содержанием жира…» | остаток ∧ уточнение |
| число | вся строка — величина (до 4 слов, без чисел) и 1–2 границы с известной единицей | значение извлекает flash-lite, сравнение — код |
| семантика | остальное; помечаются ссылки на позиции и примечания и числа в тексте | исполнитель |

Другие сноски («6)», «7)», «8)») смысла строки не меняют: их маркер просто убирается из вопроса.

### 2.3 Числа

- Значение — `Decimal`; десятичная запятая и пробелы между разрядами понимаются.
- Границы как в тексте:
  - «более» — строго, «не более» — включительно;
  - «X или более / менее» — включительно;
  - единица одной границы переходит на другую.
- Единицы переводятся только внутри своей величины:
  - кВА — полная мощность и в кВт не переводится;
  - кВт·ч — энергия, а не мощность;
  - мВт и МВт различаются по регистру; написание «мвт» в нижнем регистре не принимается.
- «%» из описания при условии в «мас.%» или «об.%» принимается с явной презумпцией в trace.
- Диапазон из описания:
  - целиком внутри интервала — T;
  - целиком снаружи — F;
  - пересекает границу — U.
- **Извлечение** делает flash-lite, один раз на ключ величины, во всех плечах одинаково.
  - Строка без названия величины («не более 3 мас.%») берёт его у числового предка, затем у соседа.
  - Величины, где одна оканчивается другой («двигатели номинальной выходной мощностью» и «номинальной выходной
    мощностью»), сводятся в одну.
  - Значение без ссылки на фрагмент или не число — U.

### 2.4 Ответ → статус

- **LLM (V1, V2)** отвечает меткой со ссылкой на фрагменты. T или F без ссылки или со ссылкой на несуществующий
  фрагмент становится U — как в протоколе доказательств v32.
- **Decision-модели (V3)** отвечают распределением. T при p(supported) ≥ 0,5; F при p(contradicted) ≥ 0,8; иначе U.
  Эти пороги нужно закрепить поправкой к предрегистрации до первого вызова V3.
- **Невалидный ответ, отказ, сбой транспорта или переполнение контекста** дают U.
  - Ответ проверяется до толкования: каждый вопрос получает ровно один ответ, ключи берутся только из вариантов,
    сумма распределения ≈ 1.
  - Переполнение обнаруживается до вызова, текст не усекается.

### 2.5 Сигналы и политики

| Сигнал | Когда | Сила |
|---|---|---|
| S1 | собственное условие строки пути = F (кроме режима) | сильный |
| S2 | на пути «прочие», а предшествующий конкретный сосед = T | сильный |
| S3 | путь альтернативы целиком T | сильный, если у пути кода есть U или F; иначе средний |
| S4 | собственное условие строки пути = U | средний |
| S5 | остаток «прочие» на пути = U | слабый |
| S6 | на развилке пути два конкретных соседа = T, или описание — ассортимент (отдельный вопрос) | сильный |
| S7 | на пути режимное условие | вопрос |

Политики — как в §5 предрегистрации:

- P1 = S1, S2, S3 сильный, S6, S7;
- P2 = P1 + S3 средний + S4;
- P3 = P2 + S5.

## 3. Что показали проверки без денег и смоук

- **DRY на `passport_regression100`** (трассы v32, текущий справочник):
  - 88 кейсов с кодом, все строятся без ошибок;
  - в среднем 13,6 вопроса на кейс (медиана 11, максимум 41), 21 числовая величина на весь набор;
  - оценка без кеша префикса: V1 — $0,30 на набор, V2 — $0,16, извлечение — $0,005.
- **Смоук V1 на M02 и H22 из разбора тихих ошибок v32:** $0,0095 за три прогона кейса, ≈ $0,0002 за вызов, 7–8 с на
  кейс при 8 параллельных вызовах.
  - **M02** (окорочка, «прочие» вместо «ножки и куски из них»): S2 — «ножки и куски из них» подтверждены; S3 на
    альтернативу из трассы 0207 14 600 9, а это эталон.
  - **H22** (диван-кровать, 9401 71): S2 — «мебель для сидения, … трансформируемая в кровати» подтверждена.
- **Что исправлено по смоуку.** Flash-lite буквально подтверждал позицию 9403 «Мебель прочая и ее части». Отсюда
  правило «прочие» в тексте позиции (§2.1): после подтверждённой 9401 позиция 9403 = F.
- **Что осталось.** Позицию 9404 «Основы матрацные; принадлежности постельные…» flash-lite для дивана-кровати тоже
  подтверждает. Это ошибка исполнителя, а не логики: такие ответы и измеряют ложные T в H2 и флаги на верных кодах в
  H1.

## 4. Ограничения первого раунда

- **Соседние позиции группы** проверяются только у «прочие» в тексте позиции. Ошибки выбора позиции видны через
  альтернативы трассы. Ошибки группы не покрыты вовсе — это Этап 2.
- **Строки с двумя величинами** («плотностью … и с содержанием серы …») и числовые строки с уточнением проверяются
  семантически. Тип такой строки — семантика с пометкой `has_number`.
- **Ссылки на позиции и примечания** («предназначенные для товаров товарной позиции 8413…») не раскрываются: условие
  помечено `interpretive`.
- **Плечи V3** не подключены: нет доступа к провайдерам (шаг 0.5 плана).
