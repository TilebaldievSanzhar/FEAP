# Frontend FEAP — дополнение v3: входы, паспорт товара, тарифные меры в проекте ДТ

> **Как читать этот документ.** Это **дельта** к `frontend_spec.md` (базовая спека) и
> `frontend_spec_dt.md` (модуль ДТ, уже нарисован и реализован в «FEAP v2.0»).
> Существующие экраны не переделываются, кроме перечисленных ниже. Документ
> самодостаточен: контракты и JSON-примеры приведены целиком. Продуктовое обоснование —
> `product_vision_v3.md`.

## 1. Продуктовый контекст (коротко)

Продукт — **одна поставка, все участники, любой пакет на выходе**. Владелец груза,
брокер, карго и банк — не разные продукты, а **входы** в одно рабочее пространство.
Всё в интерфейсе — одно из четырёх: **объект** (паспорт товара, досье поставки),
**шаг** пути, **проверка** (finding), **пакет на выходе** (ДТ, отчёты).

Принципы из `frontend_spec_dt.md` §1.1 остаются: деньги считает только код; ИИ только
предлагает; `needs_input` вместо тихого занижения; «ПРОЕКТ, не подача».

Новое в этой итерации бэкенда (всё уже реализовано):
- **Сбор за таможенные операции** считается автоматически: 0,4% от общей таможенной
  стоимости ДТ, не менее 500 и не более 250 000 сом.
- **Меры защиты рынка ЕАЭС** (антидемпинговые, специальные, компенсационные пошлины):
  справочник из реестра ЕЭК, отдельная строка в графе 47, решение декларанта по мере.
- **Соглашения о свободной торговле (ЗСТ):** признак режима по стране
  происхождения, преференциальная ставка вводится декларантом.
- **Льготы по НДС с условием** (ставка 0% только при целевом назначении): декларант
  выбирает льготу явно.
- **Изоляция организаций:** чужие задачи/OCR/сессии → 404.

## 3. «Расчёт по товару» — /calc (P0, главный экран-воронка)

### 3.1. Сценарий

```
Шаг 1. Что за товар?         [описание] или [код ТН ВЭД] (+ страна происхождения, стоимость)
Шаг 2. Код                   существующий UI классификации (needs_input, цепочка)
Шаг 3. Расчёт и ограничения  карточка-итог (ниже)
Шаг 4. Дальше                [Сохранить в Товары] [Создать поставку] [Скачать PDF (P1)]
```

### 3.2. Карточка-итог (шаг 3)

Строится из `GET /api/v1/tnved/lookup/{code}?origin=CN&on_date=2026-10-13`
плюс введённая пользователем стоимость. Пересчёт стоимости на клиенте делать
**нельзя** (деньги — только код): в P0 карточка показывает **ставки и правила**,
а суммы — только если пользователь создал поставку (тогда суммы — из проекта ДТ).
Отдельный эндпоинт расчёта сумм без досье — в планах бэкенда (§7).

```json
      "legal_ref": "ПКМ КР № 249 от 30.04.2022 (ред. ПКМ № 816 от 22.12.2025)", "note": "Зерно (пшеница и меслин)",

```

Композиция карточки:
```
┌ 7615 10 100 0 · литые ────────────────────────────── [Скопировать код] ┐
│ Пошлина ЕТТ        9%                                                  │
│ НДС                12%                                                 │
│ Акциз              нет                                                 │
│ Сбор за оформление 0,4% от ТС ДТ (мин. 500, макс. 250 000 сом)         │
│ ─────────────────────────────────────────────────────────────────────  │
│ ⚠ Антидемпинговая пошлина — может применяться                          │
│   AD-32 «Алюминиевая посуда» · КНР · 21,89% от таможенной стоимости    │
│   до 28.05.2027 · [Описание меры ▸] [Источник ЕЭК ↗]                   │
│ ⓘ Льгота НДС 0% при условии … (если есть conditional)                 │
│ ⛨ Нетарифные меры … (существующий блок НТР)                            │
└────────────────────────────────────────────────────────────────────────┘
```

Правила отображения:
- Мера защиты рынка всегда подаётся как **«может применяться»** (`status: may_apply`):
  код совпал, но мера касается товара только при совпадении описания. Описание меры
  (`product_description`) — в раскрытии, оно длинное.
- Если у меры есть ставки по производителям (`producers` непустой) — показать таблицу
  «производитель → ставка», строка с пустым `producers` = «прочие производители».
  Ставки по странам (`country`) — группировать по стране. Варианты (`variant`) —
  отдельные строки «вид товара → ставка».
- Если пользователь указал страну происхождения (`origin`), показываются только меры
  этой страны; без страны — все меры по коду с чипами стран.
- `notes` — квоты и исключения (например «не взимается в пределах 325 т для КР при
  документе о целевом назначении»): показывать как подсказку ⓘ.
- Условные льготы НДС — блок ⓘ «Возможна ставка 0% при условии …», без применения.

### 3.3. Паспорт товара (P1, объект)

Сохранённый результат расчёта = запись в «Товары» (сейчас — `POST /api/v1/catalog`
с `sku`, `description`, `hs_code`, `attributes`). В P1 карточка товара показывает:
код + обоснование (цепочка классификации), ставки и меры (тот же блок §3.2),
документы соответствия (P2), историю поставок (`usage_count`, последние досье).
Кнопка «Скачать паспорт (PDF)» — P1, бэкенд в планах.

## 4. Досье поставки: изменения формы позиции (P0)

Форма позиции (`ShipmentItemIn`, вкладка «Товары») получает новые поля:

```
manufacturer            — Производитель (гр. 31). Нужен для индивидуальных ставок
                          антидемпинговых мер. Текст.
preferential_duty_rate  — Ставка по ЗСТ, строка в формате ЕТТ ('0%', '5%').
                          Показывать только если у страны происхождения есть
                          действующее соглашение (из /reference/trade-agreements
                          или по findings W-FTA). Рядом — поле «Код преференции (гр. 36)».
vat_benefit             — Льгота по НДС с условием: select из vat.conditional[*].source
                          (из справки по коду). Пусто = общая ставка.
remedy_decisions        — Решения по мерам защиты рынка (см. §4.1). Объект
                          { "AD-32": { "decision": "applies" | "not_applicable" | "exempt",
                                       "variant": null, "rate_pct": null, "note": "…" } }
```

### 4.1. Компонент «Решение по мере защиты рынка»

Появляется в позиции, если по её коду и стране происхождения есть мера (данные —
из справки по коду или из `missing_parameters`/`tariff.remedies` проекта ДТ).

```
┌ ⚠ AD-32 · Антидемпинговая пошлина · КНР · 21,89% ─────────────────┐
│ Мера касается: штампованной и литой алюминиевой посуды … [ещё ▸]   │
│ Ваш товар подпадает под описание меры?                             │
│ (•) Да, пошлина уплачивается                                        │
│ ( ) Нет, товар не подпадает — [обоснование…]                        │
│ ( ) Освобождение: квота / целевое назначение / ценовые обязательства│
│     → нужен подтверждающий документ в «Документах»                  │
│ Производитель: [Shantui Construction Machinery Co., Ltd.] → 11,31%  │  ← если ставки по производителям
│ Вид товара: [select variants]                                       │  ← если ставки по видам (редко)
└─────────────────────────────────────────────────────────────────────┘
```

- Без выбора проект ДТ имеет статус `needs_input`, а в `missing_parameters` есть строка
  вида: «Товар 1 (7615101000): антидемпинговая мера AD-32 «Алюминиевая посуда» (CN)
  совпадает по коду — подтвердите, подпадает ли товар под описание меры
  (remedy_decisions['AD-32']: applies / not_applicable / exempt)». Кнопка-переход
  из блока «Не хватает данных» ведёт прямо к этому компоненту.
- Поле `rate_pct` (ставка вручную) скрыто за «Ставка не разобрана? Ввести вручную» —
  нужно только для мер с `needs_review` (сейчас таких нет).

## 5. Проект ДТ: изменения просмотра (P0)

### 5.1. Графа 47 — новые виды платежей

`g47[*].kind`: `duty | special | antidumping | countervailing | excise | vat` (+ `fee`
в итогах). Новое поле строки — `ref` (мера/льгота, на которой основана строка).

| kind | Подпись | code |
|---|---|---|
| duty | Пошлина | 2010 |
| special | Специальная пошлина | 2040 |
| antidumping | Антидемпинговая пошлина | 2050 |
| countervailing | Компенсационная пошлина | 2060 |
| excise | Акциз | 4010 |
| vat | НДС | 5010 |
| fee (в `totals.fee_line`) | Сбор за таможенные операции | 1010 |

Пример позиции (алюминиевая посуда из КНР, 10 000 USD по курсу 87,5, DAP):
```json
"g47": [
  { "kind": "duty", "code": "2010", "basis": "875000.00", "rate": "9%", "amount": "78750.00",
    "missing": [], "note": null, "ref": null },
  { "kind": "antidumping", "code": "2050", "basis": "875000.00", "rate": "21.89%", "amount": "191537.50",
    "missing": [], "note": "мера AD-32: Алюминиевая посуда", "ref": "AD-32" },
  { "kind": "vat", "code": "5010", "basis": "953750.00", "rate": "12%", "amount": "114450.00",
    "missing": [], "note": null, "ref": null }
],
"tariff": {
  "origin_regime": null,
  "preferential_duty_rate": null,
  "preferential_rate_applied": false,
  "remedies": [{ "measure_no": "AD-32", "kind": "antidumping", "title": "Алюминиевая посуда",
                 "decision": "applies", "notes": null, "rate": "21.89%" }],
  "vat_options": [],
  "vat_benefit": null,
  "vat_benefit_applied": false
}
```
Итоги:
```json
"totals": {
  "g12": "875000.00",
  "payments": { "duty": "78750.00", "excise": "0.00", "vat": "114450.00",
                "antidumping": "191537.50", "fee": "3500.00" },
  "fee_line": { "kind": "fee", "code": "1010", "basis": "875000.00",
                "rate": "0.4% от таможенной стоимости (не менее 5 РП = 500 сом, не более 2500 РП = 250000 сом)",
                "amount": "3500.00", "note": "ПП КР № 79 от 13.02.2020, п. 38 (…)" }
}
```

- `items[i].tariff` — **не графа**, а след проверок: показывать в раскрытии позиции как
  «Тарифные меры» (режим страны, меры и решения, льготы НДС). В печатную форму не идёт.
- Строку пошлины защиты рынка выделять (это часто крупнее пошлины ЕТТ): чип `AD-32`,
  тултип с названием меры.
- Карточка «К уплате (проект)»: пошлина + пошлины защиты рынка + акциз + НДС + сбор.
  Ключи `payments` динамические — рендерить все пришедшие.
- `meta.vat_base_includes_remedies` (bool) и `meta.fee_mode` (`percent | fixed | off`) —
  мелким текстом под итогами («База НДС: без антидемпинговой пошлины»).

### 5.2. Новые правила в findings-панели

| Правило | Severity | Смысл | Действие в UI |
|---|---|---|---|
| F-16 | error | Ставка ЗСТ заявлена, но не применена (нет соглашения / нет кода в гр. 36) | якорь на гр. 36 |
| F-17 | error | Выбрана льгота НДС, неприменимая к коду на дату | якорь на поле льготы |
| W-FTA | info | У страны есть действующее ЗСТ — возможна преференция при сертификате происхождения | показать поле «Ставка по ЗСТ» |
| I-EAEU | info | Страна происхождения — член ЕАЭС (такие товары обычно не декларируются) | — |
| W-REMEDY-EXEMPT | warning | Освобождение от меры без подтверждающего документа в гр. 44 | переход во вкладку «Документы» |
| I-REMEDY-NA | info | Декларант указал «не подпадает» — сохранить обоснование | — |
| W-REMEDY-VAT | warning | Начислена пошлина защиты рынка; учёт в базе НДС не сверен с практикой ГТС | — |
| W-VAT-COND | warning | Возможна льгота НДС 0% при условии — применена общая ставка | select льготы в позиции |
| I-VAT-COND | info | Применена льгота НДС по выбору — приложить подтверждение целевого назначения | — |
| W-FEE | info | Сбор не рассчитан (нет ТС или расчёт отключён) | — |

Для легенды правил: обновить тултип F-10 — «арифметика графы 47, база НДС = ТС +
пошлина + акциз (+ пошлины защиты рынка, если включено)».

## 6. Справочники (P1)

### 6.1. Меры защиты рынка ЕАЭС — /reference/remedies
Список мер (источник — те же данные, что в справке по коду). Колонки: номер (AD-32),
товар, страны, ставка/диапазон, действует до, статус (`applied` — применяется,
`suspended` — временно не применяется). Поиск по коду ТН ВЭД (префикс) и по стране.
Карточка меры = блок из §3.2.

`GET /api/v1/reference/trade-remedies?code=7615&origin=CN&on_date=2026-10-14` (все
параметры необязательны; без них — весь реестр по порядку номеров):
```json
[
  { "measure_no": "AD-32", "kind": "antidumping", "title": "Алюминиевая посуда",
    "product_description": "Штампованная и литая алюминиевая посуда …",
    "countries": ["CN"], "codes": ["7615101000", "7615108009", "7616991008", "7616999008"],
    "rates": [{ "rate_pct": "21.89", "country": null, "producers": [], "variant": null }],
    "valid_from": "2021-09-25", "valid_to": "2027-05-28", "notes": null,
    "legal_basis": "Решение Коллегии ЕЭК …", "source_url": "https://remedies.eaeunion.org/…",
    "needs_review": false, "status": "applied" }
]
```
`code` — префикс 2–10 цифр, совпадение в обе стороны: «7615» находит меру на
7615101000, а 10-значный код товара — меру уровня позиции («7210»). `origin` — ISO-2
(страны ЕС совпадают с мерами на «EU»). Истёкшие меры не возвращаются.

### 6.2. Торговые соглашения — /reference/agreements
`GET /api/v1/reference/trade-agreements`:
```json
[
  { "country": "AE", "regime": "fta",
    "agreement": "Соглашение о свободной торговле между ЕАЭС и его государствами-членами и Объединёнными Арабскими Эмиратами (подписано 27.06.2025, Минск)",
```

## 7. Технические изменения для фронтенда (не дизайн)

1. **SSE прогресса задач:** `GET /api/v1/jobs/{id}/events` теперь принимает
   `?access_token=<JWT>` — нативный `EventSource` не умеет заголовки. С токеном бэкенд
   проверяет, что задача принадлежит организации; без токена в `AUTH_MODE=optional`
   работает как раньше, в `required` — 401. В `useJobLive.ts` и `api/client.ts`
   добавить токен в URL.
2. **404 вместо чужих данных:** `/jobs/*`, `/ocr/jobs/*`, `/classify/{session}/answer` для
   объектов другой организации отвечают 404 — показывать стандартное «Не найдено».
3. Справка по коду: новые query-параметры `origin` (ISO-2) и `on_date` (YYYY-MM-DD).
4. Суммы — строки (Decimal), не парсить в float; ключи `totals.payments` динамические.
5. Перегенерировать типы из `/openapi.json` (новые поля `ShipmentItemIn`, `PaymentLine.ref`,
   `CodeLookupResponse.trade_remedies/customs_fee`, `VatInfo.conditional`).

Планы бэкенда, под которые можно оставить место в дизайне (не реализовано):
`POST /api/v1/calc` — расчёт сумм по товару без досье (стоимость, страна, производитель →
платежи); `POST /api/v1/passports` + PDF паспорта. List-эндпоинт мер защиты рынка
реализован (§6.1).
