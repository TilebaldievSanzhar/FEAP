## 0. TL;DR

- **Конечный результат — по-прежнему ДТ**, но шире формы из 54 граф: продукт выдаёт
  **пакет на выходе поставки**. ДТ — флагман; рядом ДТС, КДТ, пакет для банка, пакет
  экспортёра в РФ, формы импорта из ЕАЭС, пакет для защиты перед инспектором.
  Смена канала подачи (АРМ «Брокер» → «Смарт Бажы») — это замена модуля выгрузки,
  а не переделка продукта.
- **Весь путь УВЭД** — видение, с границей: продукт **готовит, считает, проверяет,
  объясняет и передаёт**, но не исполняет (не подаёт ДТ под своей ЭЦП, не возит,
  не платит, не выдаёт сертификаты).
- **Разные пользователи — участники одной поставки, а не разные рынки.** Владелец
  груза, его брокер, банк, карго работают с одним досье. Строим общее ядро для всех,
  **продаём по одному сегменту за раз**.
- **Цельность обеспечивают два объекта и четыре примитива** (§2): всё, что не
  ложится в эту модель, не делаем.
- **Релиз 1 начат в этой итерации:** сбор 0,4% по п. 38 ПП № 79, меры защиты рынка
  ЕАЭС из реестра ЕЭК (28 мер), режимы ЗСТ, НДС 0% по ПКМ № 816/249/264, изоляция
  данных между организациями (§8).

## 2. Модель продукта: два объекта, четыре примитива

**Объекты**
1. **Паспорт товара** — код ТН ВЭД с обоснованием, ставки (ЕТТ, НДС, акциз,
   антидемпинг), нетарифные меры, ограничения, документы соответствия, история
   поставок. Переиспользуется в каждой поставке, платеже, сертификации, карточке
   маркетплейса.
2. **Досье поставки** — стороны, документы, позиции (ссылки на паспорта),
   стоимость, платежи, проверки, итог выпуска.

**Примитивы** — любая фича является одним из них:

| Примитив | Что это | Примеры |
|---|---|---|
| Объект | паспорт, досье, документ компании | паспорт товара, сертификат с датой окончания |
| Шаг | этап пути поставки | расчёт → документы → ДТ → выпуск → архив |
| Проверка | finding с правилом, severity и якорем | F-16, W-REMEDY-VAT, «сертификат заблокирован в РФ» |
| Пакет | выходной артефакт | ДТ (PDF/XLSX/XML), ДТС, пакет для банка |

```
 КТО ВХОДИТ             ЯДРО (общее для всех)                     ПАКЕТЫ НА ВЫХОДЕ
 Частное лицо ─┐                                                  ДТ: PDF · XLSX · XML · под форму подачи
 Компания/ИП  ─┤   ПАСПОРТ ТОВАРА ─────► ДОСЬЕ ПОСТАВКИ ─────►    ДТС-1/2 · КДТ · экспортная ДТ
 Брокер       ─┼─► код+обоснование       документы, позиции,      Пакет для банка
 Карго        ─┤   ставки, документы,    стоимость, платежи,      Пакет экспортёра в РФ
 Банк         ─┘   ограничения           проверки                 Формы для импорта из ЕАЭС
                          ▲                      │                Пакет для защиты перед инспектором
                          └──── память ◄─────────┘ (итог выпуска → каталог, прецеденты)
```

**Фильтр для новой фичи.** Фича работает с паспортом или досье; является шагом,
проверкой или пакетом; полезна хотя бы двум типам пользователей; делается без
интеграций. Иначе — не делаем (трекинг грузов, TMS, бухгалтерия, подача ДТ).

**Цикл, который даёт ров:** товар → поставка → пакет → итог выпуска → память
(каталог, прецеденты) → следующая поставка быстрее и безопаснее.

## 3. Входы (кто и как пользуется)

| Вход | Что делает | Что видит | Оплата (гипотеза) |
|---|---|---|---|
| Частное лицо | мастер: авто / посылка / разовый ввоз → расчёт → список документов → «найти брокера» | упрощённый мастер | бесплатно; позже — заявки брокерам |
| Компания или ИП (владелец груза) | товары, поставки, расходы, документы; «передать брокеру» или «подать самому» (личный кабинет «Смарт Бажы»); второе мнение по ДТ брокера | рабочее пространство компании | подписка по объёму |
| Брокер / декларант | очередь досье клиентов, подготовка ДТ, проверки, выгрузки, ссылка для клиента | рабочее место | места + ДТ; клиенты брокера бесплатно |
| Карго | Excel → коды и расчёт по позициям, калькулятор под своим брендом | пакетный режим | за строку |
| Банк | «проверить платёж»: инвойс → паспорта → ограничения | консоль проверки | подписка или API |

Порядок: сначала каждый получает пользу в одиночку, потом — совместная работа над
одним досье (общий доступ между организациями, ссылка клиента).

## 5. Фичи с эффектом «вау» (в рамках модели)

1. Скриншот товара с 1688 → паспорт товара за минуту (мультимодальная модель, без парсинга сайтов).
2. Китайский инвойс → готовая графа 31 на русском.
3. Пакет для защиты одной кнопкой: цепочка обоснования кода с цитатами примечаний и пояснений + обоснование стоимости.
4. Светофор перед подачей: проверка пакета так, как его будет проверять машина ГТС.
5. Ссылка брокера для клиента: клиент с телефона отправляет документы — у брокера заполненное досье.
6. Второе мнение по ДТ брокера: компания загружает декларацию — получает отчёт о рисках.
7. «Что изменится для меня»: уведомления по кодам каталога (ставки, НТР, антидемпинг, санкции, ГС 2028).
8. Самоаудит за 3 года: архив ДТ → карта рисков и возможных переплат.

## 6. Чего не хватает кроме фич

1. **Платящих клиентов** — 0; видение без выручки — риск номер один.
2. **Эксперта-декларанта** рядом (команда или советник): эталоны, спорные кейсы, доверие рынка.
3. **Регулярного обновления справочников** — еженедельная сверка ЕЭК (ЕТТ, меры
   защиты рынка), ГНС/Кабмина (льготы НДС), ГТС (сборы), санкционных списков;
   «источник и дата сверки» в интерфейсе. Для мер защиты рынка конвейер уже есть
   (`scripts/fetch/eaeu_remedies.py`).
4. **Доверия**: изоляция данных (сделано), персональные данные по Цифровому кодексу
   (минимизация перед LLM, оферта), юридическая упаковка.
5. **Каналов продаж**: ассоциация брокеров, карго, «Кыргыз Экспорт», банки, Telegram.
6. **Бренда** — FEAP рабочее название.

## 8. Сделано в этой итерации (2026-10-13)

**Деньги (Релиз 1, срочное):**
- **Сбор** — `feap/tariff/fees.py`: 0,4% от общей таможенной стоимости ДТ, не менее
  5 и не более 2500 РП (РП = 100 сом, настройка `DT_CALC_INDEX_KGS`); ред. п. 38 ПП КР
  № 79 по ПКМ № 349/406/444, текст сверен по alta.ru. Режимы `DT_CUSTOMS_FEE_MODE =
  percent | fixed | off`.
- **Меры защиты рынка ЕАЭС** — `feap/tariff/remedies.py` + таблица `trade_remedies`:
  снимок открытого реестра ЕЭК (remedies.eaeunion.org, 28 действующих/приостановленных
  мер, ставки по производителям, странам и видам товара). В ДТ — строка графы 47 вида
  2050 (антидемпинговая), 2040/2060 — специальная/компенсационная. Совпадение по
  коду+стране = «может применяться»: решение `applies | not_applicable | exempt`
  принимает декларант; без решения проект ДТ уходит в `needs_input`.
- **ЗСТ** — `feap/tariff/agreements.py` + `trade_agreements`: Вьетнам, Сербия, Иран,
  ОАЭ (с 06.10.2026), Монголия (временное, с 22.07.2026); Индонезия — подписано,
  не действует. Преференциальная ставка применяется только при действующем режиме,
  коде в графе 36 и сертификате происхождения (F-13/F-16).
- **НДС 0%** — `scripts/seed/vat_benefits.py`: ПКМ № 816 прил. 1 (без условий, с
  сезонными окнами), прил. 2 и ПКМ № 249/264 (только по выбору декларанта, F-17,
  W-VAT-COND). Ставки и льготы берутся на дату расчёта досье, а не «сегодня».
- **База НДС и антидемпинг**: ст. 310 НК КР включает «таможенные пошлины и налоги»;
  включаются ли антидемпинговые пошлины — норма прямо не говорит → настройка
  `DT_VAT_INCLUDE_REMEDY_DUTIES` (по умолчанию нет) + всегда W-REMEDY-VAT.
- **Коды видов платежей** 1010/1020/2010/2040/2050/2060/2140–2160/5010 сверены с
  Прил. 9 к Решению КТС № 378 (раздел ЕАЭС); 4010 (акциз) — национальный, не сверен.
- Справка `/tnved/lookup/{code}` отдаёт меры защиты рынка, условные льготы НДС и
  правило сбора; новый `/reference/trade-agreements`.

**Безопасность:** `org_id` у задач классификации, OCR-задач и сессий уточнений
(миграция 012); `/jobs/*`, `/ocr/jobs/*`, `/classify/{session}/answer`, привязка
OCR-документа к досье проверяют владельца (чужое = 404). SSE принимает
`?access_token=` (EventSource не умеет заголовки).

**Проверено:** 505 тестов. Миграция 012 — офлайн-SQL; на живой БД не прогонялась
(Docker не был запущен).

## 9. Метрики

- **North Star** без изменений: товарные позиции, прошедшие через платформу за месяц.
- **Цельность:** доля поставок, где использовано ≥3 модулей (расчёт → документы → пакет).
- **Деньги:** доля проектов ДТ, где платежи совпали с фактом выпуска (по фидбеку итога).
- **Пилоты:** 3 платящих до конца ноября 2026; 1 LOI от банка.

## 10. Открытые вопросы

1. «Смарт Бажы»: есть ли загрузка файлов; что с АРМ «Брокер»; тарифы (кастдев).
2. Учёт антидемпинговых пошлин в базе НДС — практика ГТС (спросить у брокеров с кейсами AD-32/AD-39).
3. Формы документов о происхождении по каждому ЗСТ и графики ставок — отдельный набор данных.
4. Единая система тарифных преференций ЕАЭС (развивающиеся/наименее развитые страны) — перечни стран и товаров не загружены.
5. Код вида платежа для акциза в национальном разделе КР (сверить по реальной ДТ).
