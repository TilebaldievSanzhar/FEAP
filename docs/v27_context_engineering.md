## 1. Проблема

### 1.1 Стагнация метрик

Последние итерации (v21–v26) показали стагнацию метрик несмотря на изменения SGR-полей, промптов и структур:

| Версия | Heading | Subheading | Code-8 | Code-10 | Основное изменение |
|:------:|:-------:|:----------:|:------:|:-------:|:-------------------|
| v16*   | 97%     | 91%        | 81%    | 77%     | Рабочий SGR |
| v21    | 97%     | 88%        | 77%    | 74%     | SGR + qualifier_check |
| v22    | —       | 85%        | 71%    | 69%     | DTN (провал) |
| v24    | —       | —          | —      | —       | Возврат к SGR |
| v25    | 98%     | 89%        | 81%    | 76%     | Stable SGR |
| v26    | 98%     | 87%        | 81%    | 78%     | + все group notes для L4/L5 |

v26 добавил **все** примечания группы для L4/L5, результат — 7 исправлений, но **5 регрессий**, итог ≈ нулевой.

### 1.2 Ключевое наблюдение

Анализ 22 ошибок v26 и 24 ошибок v25 выявил **17 персистентных ошибок** — одинаковых в обоих прогонах. Эти ошибки не реагируют на изменения промптов/SGR.

**Корневая причина**: проблема не в reasoning pipeline (как модель думает), а в **data pipeline** (что модель видит). Итерации SGR/промптов дают ±2-3% стохастического шума, а не системное улучшение.

## 3. Найденные пробелы в контекстных данных

### 3.1 Section notes не загружались для L4/L5

Level4 загружал только `get_notes(db, "group", group_code)`. Примечания к **разделу** (section) не передавались, хотя содержат критические определения:

- **Раздел XI** (текстиль): определение "готовые" (прим.7), определения типов пряжи/ткани (прим.11-12)
- **Раздел XVI** (машины): определение терминов (прим.5)
- **Раздел XVII** (транспорт): определение "бывшие в эксплуатации" (прим.2)

### 3.2 Кросс-групповые определения недоступны

Некоторые группы определяют термины **для всей Номенклатуры**:

| Группа | Примечание | Определяет | Область действия |
|--------|:----------:|-----------|:----------------:|
| 51 | 1 | "шерсть" = овцы/ягнята, "тонкий волос" = альпака, кашмир... | Вся Номенклатура |
| 54 | 1 | Определения химических нитей/волокон | Вся Номенклатура |
| 39 | 1 | Определения пластмасс | Вся Номенклатура |
| 72 | 1 | Определения черных металлов | Вся Номенклатура |
| 84 | 10 | Определения машинного оборудования | Вся Номенклатура |

Пример: при классификации свитера (группа 61) модель не видит определение из группы 51: *«шерсть означает шерсть овец или ягнят»* → не может правильно различить «шерстяная пряжа» (611011) от «тонкий волос» (611019).

### 3.3 Все group notes = шум

v26 загружал ВСЕ примечания группы (10-15 штук). Для L4/L5 критичны только:
- **субп.*** — примечания к субпозициям (75 штук в БД)
- **доп.*** — дополнительные примечания (46 штук в БД)
- **definition** — определения терминов

Остальные (inclusive/exclusive/general с обычными номерами) — это примечания уровня позиций/группы, уже использованные на L2/L3 и создающие шум на L4/L5.

## 4. Реализованные изменения

### 4.1 Новые DB queries

**Файл**: `src/feap/db/queries.py`

| Функция | Назначение | Что возвращает |
|---------|-----------|---------------|
| `get_subposition_notes(db, group_code)` | Только субп./доп./definition примечания группы | Фильтр: `note_number LIKE 'субп.%' OR 'доп.%' OR note_type='definition'` |
| `get_section_definition_notes(db, section_code)` | Определения терминов из примечаний раздела | Фильтр: `note_type='definition'` |
| `get_cross_group_definitions(db, group_code)` | Глобальные определения из связанных групп | Маппинг групп + фильтр по «Номенклатур» |

**Маппинг кросс-групповых зависимостей** (в `get_cross_group_definitions`):

```
Группы 50-63 (текстиль) ← определения из групп 51, 54
Группы 73-83 (металлы)  ← определения из группы 72
Группа 40 (резина)      ← определения из группы 39
Группа 41-42 (кожа)     ← определения из групп 40, 41, 43
```

### 4.2 Изменения в level handlers

**Файлы**: `src/feap/cascade/levels/level4.py`, `src/feap/cascade/levels/level5.py`

**Было** (v26):
```python
group_notes_rows = await get_notes(db, "group", group_code)  # ВСЕ примечания группы
```

**Стало** (v27):
```python
# 1. Только субпозиционные + определения
subp_notes_rows = await get_subposition_notes(db, group_code)

# 2. Определения из раздела
section_rows = await get_section_definition_notes(db, section_code)

# 3. Кросс-групповые определения
cross_def_rows = await get_cross_group_definitions(db, group_code)
```

### 4.3 Изменения в PromptAssembler

**Файл**: `src/feap/prompts/assembler.py`

- Методы `level4()`, `level5_branch()`, `level5()` получили параметры `section_notes` и `cross_group_notes`
- Добавлена функция `_merge_definition_notes()` — объединяет три типа примечаний с дедупликацией по `(scope_type, scope_code, note_number)`
- Порядок в контексте: section definitions → cross-group definitions → subposition notes

### 4.4 Обновление промптов

**Файлы**: `src/feap/prompts/templates/system/level4_subposition.jinja2`, `level5_branch.jinja2`, `level5_subsubposition.jinja2`

Добавлено правило:
```
ОПРЕДЕЛЕНИЯ: если в ПРИМЕЧАНИЯХ есть определения терминов (напр. «шерсть означает...»,
«бывшие в эксплуатации — ...»), ОБЯЗАТЕЛЬНО используй их при классификации.
Термины в ТН ВЭД имеют юридические определения, отличные от бытового значения.
```

### 4.5 Объём контекста до/после

Пример для группы 61 (текстиль):

| Источник | v26 (всё) | v27 (фильтр) |

## 7. Аудит ground truth — подозрительные кейсы

Следующие кейсы из бенчмарка требуют проверки с таможенным экспертом:

### 7.1 BENCH-H19: Пикап дизельный 2.4 л

- **Описание**: Пикап с двойной кабиной, дизель 2.4 л, полный привод, грузоподъёмность ~1.2 т
- **GT**: `8704239809` → субпозиция 870423 (полная масса **более 20 т**)
- **PRED**: `8704219200` → субпозиция 870421 (полная масса **не более 5 т**)
- **Подозрение**: пикап с 2.4L дизелем физически не может весить >20 т. Типичная полная масса ~3-3.5 т → 870421 верно. GT, вероятно, ошибочен.
- **Рекомендация**: проверить источник GT. Если ФТС решение — возможно, код был присвоен другому ТС в том же решении.

### 7.2 BENCH-M22: Свитер 100% мерино

- **Описание**: Свитер мужской, 100% шерсть мериноса
- **GT**: `6110191009` → субпозиция 611019 («прочие» под «шерстяная пряжа или тонкий волос»)
- **PRED**: `6110113000` → субпозиция 611011 («из шерстяной пряжи»)
- **Подозрение**: Примечание 1(а) к Группе 51: *«шерсть означает шерсть овец или ягнят»*. Мерино — порода овец. Следовательно, мериносовая шерсть = «шерсть» = 611011, а не «прочие» 611019.
- **Рекомендация**: 611011 может быть правильным ответом. Уточнить, использует ли GT определение из Группы 51.

### 7.3 BENCH-H30: Колонка Bluetooth с двумя динамиками

- **Описание**: Колонка портативная, **два динамика + пассивный излучатель**, в одном корпусе
- **GT**: `8518210000` → 851821 («громкоговорители одиночные, смонтированные в корпусах»)
- **PRED**: `8518220009` → 851822 («комплекты громкоговорителей, смонтированных в одном корпусе»)
- **Подозрение**: описание буквально указывает «два динамика» → это комплект (851822), а не одиночный (851821). PRED может быть правильнее GT.
- **Рекомендация**: уточнить, классифицируются ли портативные колонки с несколькими драйверами как 851821 или 851822 по таможенной практике.

### 7.4 BENCH-H05: Сыр твёрдый выдержанный (Нидерланды)

- **Описание**: Сыр твёрдый выдержанный, Нидерланды, 5 кг, вакуумная упаковка
- **GT**: `0406900100` → «для производства плавленых сыров»
- **PRED**: `0406909909` → «прочие»
- **Подозрение**: описание не указывает назначение «для производства плавленых сыров». Без этого указания сыр из Нидерландов (вероятно, Гауда) должен быть `0406907800` (Гауда) или `0406909909` (прочие). GT код подразумевает промышленное назначение, не указанное в описании.
- **Рекомендация**: проверить, содержит ли исходный документ GT указание на целевое использование.

### 7.5 BENCH-H21: Портативная зарядная станция

- **Описание**: Power station, LiFePO4 1024 Вт·ч, инвертор 1800 Вт, AC/DC/USB выходы
- **GT**: `8507600000` → 8507 (аккумуляторы, литий-ионные)
- **PRED** (v26): `8504408500` → 8504 (статические преобразователи)
- **Подозрение**: в v25 модель правильно выбрала 8507. Это пограничный случай — power station содержит и аккумулятор, и инвертор. По ОПИ 3б основной характер определяется аккумулятором → 8507 верно, но это легитимно спорный случай.
- **Рекомендация**: GT корректен (8507), но кейс genuinely hard. Нестабильность между v25/v26 связана с изменением контекста.

## 8. Ключевые выводы

### 8.1 Почему SGR/промпт итерации не давали скачок

1. **Reasoning ≠ Data**: SGR направляет *как* модель думает, но не может компенсировать отсутствие *что* она видит
2. **Закон убывающей отдачи**: SGR-поля уже охватывают основные паттерны (пороги, специфичность). Дальнейшие reasoning-поля дают diminishing returns
3. **Шум vs сигнал**: добавление контекста (v26 notes) без фильтрации ухудшает, а не улучшает

### 8.2 Принципы context engineering для L4/L5

1. **Targeted > Complete**: лучше 5KB релевантных определений, чем 30KB полных примечаний
2. **Definitions are king**: на уровне субпозиций основная ценность примечаний — определения терминов
3. **Cross-level context**: определения из одной группы могут быть критичны для другой (группа 51 → группа 61)
4. **Section notes matter**: определения уровня раздела игнорировались, хотя действуют на все группы раздела
